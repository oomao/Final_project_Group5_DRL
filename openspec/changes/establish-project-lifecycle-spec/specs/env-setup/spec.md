## ADDED Requirements

### Requirement: Python Version Lock
The project SHALL support only Python 3.11.x. `pyproject.toml` MUST declare `requires-python = ">=3.11,<3.12"`. Python 3.12 and later SHALL be rejected because the stdlib `ast` module changed shape and `ast-buffer-manager` depends on the 3.11 node layout.

#### Scenario: Python 3.12 install fails
- **WHEN** a developer with Python 3.12 active runs `uv sync` or `pip install -e .`
- **THEN** the install MUST fail with a `requires-python` mismatch error
- **AND** the error message MUST mention 3.11.x as the required range

#### Scenario: Python 3.11 install succeeds
- **WHEN** a developer with Python 3.11.x active runs `uv sync`
- **THEN** the install MUST complete without version warnings

### Requirement: CUDA and PyTorch Wheel Lock
The project SHALL pin `torch==2.5.1` and use the cu121 PyPI index for Windows and Linux. RTX 4090 (sm_89) is verified on cu121, and upgrading CUDA gives no measured benefit for vanilla DQN on LunarLander-v3.

#### Scenario: Install on RTX 4090 + Windows 11 + Python 3.11
- **WHEN** the developer runs `uv sync` on the target hardware
- **THEN** `torch.cuda.is_available()` MUST return `True`
- **AND** `torch.version.cuda` MUST equal `"12.1"`

#### Scenario: Install on a machine without an NVIDIA GPU
- **WHEN** the developer runs `uv sync` on a Mac or a Linux box without CUDA
- **THEN** the resolver MUST fall back to the CPU-only `torch` wheel
- **AND** the smoke test (Requirement: Smoke Test) MUST pass on CPU

### Requirement: Environment Manager
The project SHALL use `uv` as the primary environment and dependency manager. `pyproject.toml` + `uv.lock` SHALL be the single source of truth. `requirements.txt` MAY be kept as a fallback for `pip`-only environments but MUST be regenerated by `uv export -o requirements.txt` and SHALL NOT be hand-edited.

#### Scenario: Fresh teammate clones the repo
- **WHEN** a teammate runs `git clone <repo> && cd <repo> && uv sync`
- **THEN** the `.venv` MUST be created and all dependencies installed in under 60 seconds on a typical broadband connection

#### Scenario: Pip fallback path
- **WHEN** a developer cannot install `uv` and runs `pip install -r requirements.txt`
- **THEN** the install MUST succeed against the same pin set declared in `pyproject.toml`
- **AND** `requirements.txt` MUST have been generated by `uv export` in the latest commit

#### Scenario: Hand-edited requirements.txt is rejected
- **WHEN** a PR modifies `requirements.txt` without a corresponding change to `uv.lock`
- **THEN** the reviewer SHALL request the file be regenerated via `uv export`

### Requirement: Dependency Lockfile Committed
`uv.lock` MUST be committed to git. New dependencies MUST be added via `uv add <package>` (which updates both `pyproject.toml` and `uv.lock`) and MUST NOT be added by manually editing `pyproject.toml`.

#### Scenario: Lockfile drift detected
- **WHEN** CI or pre-commit detects `pyproject.toml` was edited without an accompanying `uv.lock` update
- **THEN** the commit/PR SHALL be rejected with a "lockfile out of sync" message

### Requirement: API Key Management via .env
All external API keys (Gemma, future LLM providers) MUST be loaded via a `.env` file using `python-dotenv`. `.env` MUST appear in `.gitignore`. A documentation-only `.env.example` MUST be committed with all required keys present but values blank. The source tree MUST NOT contain any hardcoded API key.

#### Scenario: Hardcoded Gemini key is detected
- **WHEN** the pre-commit hook scans for the regex `AIza[0-9A-Za-z_-]{35}`
- **THEN** any match in tracked files MUST cause the commit to be rejected

#### Scenario: .env.example is present
- **WHEN** a fresh clone is inspected
- **THEN** `.env.example` MUST exist at repo root
- **AND** MUST list `GOOGLE_API_KEY=` and `GEMMA_MODEL=` keys with blank values

### Requirement: Pre-commit Configuration
The project SHALL ship a `.pre-commit-config.yaml` with at least `ruff check --fix`, `ruff format`, and an `openspec validate --strict` hook that runs on every change directory under `openspec/changes/`. Total hook wall-time SHOULD be under 3 seconds for a typical commit. `mypy` and `pytest` SHALL NOT be in pre-commit (they belong to CI).

#### Scenario: Pre-commit auto-fixes formatting
- **WHEN** a developer commits a `.py` file with format violations
- **THEN** `ruff format` MUST auto-fix the file and re-stage it

#### Scenario: Pre-commit blocks invalid spec
- **WHEN** a developer modifies `openspec/changes/<name>/specs/...` such that `openspec validate <name> --strict` fails
- **THEN** the commit MUST be blocked until the spec is valid

### Requirement: Reproducibility Boundaries
Under the same OS family + same `torch` wheel + same seed, DQN training output MUST be bit-exact for the per-episode `return` field. Across OS families or CUDA versions, the 3-seed mean of `mean_reward_last100` SHOULD differ by less than 5% from the reference run on Windows 11 + RTX 4090 + cu121.

#### Scenario: Same machine, same seed, two consecutive runs
- **WHEN** the developer runs `python -m hermes_dqn.training.train --episodes 100 --seed 42` twice on the same `.venv`
- **THEN** the two `episodes.jsonl` files MUST have identical `return` values for every episode

#### Scenario: Cross-OS drift exceeds tolerance
- **WHEN** the 3-seed mean of `mean_reward_last100` on macOS differs from the Windows 4090 reference by ≥ 5%
- **THEN** the discrepancy MUST be logged as a `known-drift` entry in the run's `config.json`

### Requirement: Smoke Test
The project SHALL provide a single command that proves the environment is healthy. The PASS criteria are: `python -m hermes_dqn.training.train --episodes 10 --seed 42` MUST complete in under 60 seconds wall-time, exit with code 0, and produce `runs/<timestamp>/` containing `config.json`, `episodes.jsonl`, and `model_final.pt`.

#### Scenario: Smoke test PASS
- **WHEN** the developer runs the smoke command on a freshly synced env
- **THEN** the three artifact files MUST exist
- **AND** wall-time MUST be < 60 s

#### Scenario: Smoke test FAIL
- **WHEN** the smoke command exits non-zero or any of the 3 artifact files is missing
- **THEN** the developer MUST NOT proceed to a full 1500-episode run

### Requirement: CPU Fallback Performance
On a machine without CUDA, a full 1500-episode baseline run MUST complete in under 120 minutes of wall-time. This bounds the worst-case CPU-only iteration cost so a teammate without a GPU is not blocked from contributing.

#### Scenario: CPU baseline within budget
- **WHEN** `python -m hermes_dqn.training.train --episodes 1500 --seed 42` is launched on a typical 8-core CPU laptop
- **THEN** the run MUST complete in < 120 minutes

### Requirement: 4090 Shared-Machine Protocol
Local dev experiments SHALL be capped at ≤ 300 episodes. All official 1500-episode × 5-seed runs MUST execute on the shared RTX 4090 machine. The 4090 SHALL be reserved through TWO complementary mechanisms: (a) a `docs/4090-booking.md` markdown table updated via PR or GitHub Issues with the `gpu-claim` label, AND (b) a runtime guard `scripts/claim-gpu.sh` that runs `nvidia-smi` and aborts if GPU utilisation > 50% (someone is already running).

#### Scenario: Local long run is rejected
- **WHEN** a developer tries to launch a 1500-episode run on their laptop
- **THEN** `train.py` MUST print a warning that 1500-episode runs belong on the 4090

#### Scenario: nvidia-smi guard aborts overlapping run
- **WHEN** the developer runs `scripts/claim-gpu.sh` and `nvidia-smi` reports GPU 0 utilisation > 50%
- **THEN** the script MUST exit non-zero and print the currently-running PID/user

#### Scenario: Booking entry missing
- **WHEN** the developer launches a 1500-episode run on the 4090 without an entry in `docs/4090-booking.md` for the current time window
- **THEN** `scripts/claim-gpu.sh` SHALL print a warning but MUST NOT abort

### Requirement: Training Output Disk Hygiene
The `runs/` directory MUST be in `.gitignore`. Local machines SHOULD keep the most recent 10 runs and the 4090 machine SHOULD keep the most recent 30. The project MUST provide `tools/cleanup_runs.py --keep N` to enforce the cap.

#### Scenario: Local cleanup invocation
- **WHEN** the developer runs `python tools/cleanup_runs.py --keep 10`
- **THEN** all but the 10 newest entries under `runs/` MUST be deleted

#### Scenario: Cleanup respects evaluation hierarchy
- **WHEN** `runs/` contains both flat-timestamp and `runs/<exp>/<condition>/seed_NN/` hierarchies
- **THEN** the cleanup tool MUST treat each top-level directory (timestamp OR experiment name) as one unit
